# Justificación de métricas y parámetros

Se utilizó **accuracy** como métrica principal porque mide la proporción de clasificaciones correctas y permite comparar de forma descriptiva con el artículo, como solicita la actividad. También se calcularon precisión, recall y F1 macro para examinar los errores dando el mismo peso a cada una de las diez clases. La pérdida logarítmica permitió observar el aprendizaje y desempatar configuraciones con la misma accuracy de validación. **Los valores de accuracy son resultados calculados, no parámetros fijados:** en prueba se obtuvieron 47.5% sin Longitud (19 de 40 aciertos) y 35% con características reducidas (14 de 40).

Se probaron redes de **16, 32 y 32–16 neuronas**, con ReLU o tanh, para explorar distintas capacidades sin utilizar modelos demasiado grandes para 200 registros. Se eligió la red de **16 neuronas ReLU en la época 53** por su accuracy de validación de 47.5%. La red de 32–16 alcanzó la misma accuracy, pero tuvo mayor pérdida de validación (2.678 frente a 1.588). Las 600 épocas fueron un presupuesto para observar las curvas; no significa que se usara el modelo de la última época. La fase reducida mantuvo la configuración y la época de su pareja original para comparar bajo las mismas condiciones.

Se utilizó **Adam**, tasa de aprendizaje **0.001**, regularización **alpha=0.001** y lotes de **16** como una configuración inicial sencilla: una tasa moderada para actualizar los pesos, penalización de pesos grandes para limitar el sobreajuste y lotes pequeños para el conjunto de entrenamiento. Estos valores no se optimizaron de forma exhaustiva ni se consideran los mejores posibles. La división estratificada **60/20/20** reservó 120 registros para entrenar, 40 para elegir configuración y 40 para evaluar; la semilla **42** permite repetir las particiones y la inicialización, sin implicar una ventaja especial de ese número.

El umbral **|r| > 0.8** se tomó de las instrucciones del profesor. La estandarización z-score y la selección por correlación se ajustaron solo con entrenamiento. La reducción dejó 17 de las 29 características permitidas y disminuyó la accuracy de prueba en **12.5 puntos porcentuales** en esta partición. Con solo 40 registros de prueba, cada acierto cambia la accuracy en 2.5 puntos; el resultado no demuestra que la reducción siempre perjudique al modelo.
